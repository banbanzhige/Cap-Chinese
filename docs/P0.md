# P0：技术验证边界

目标：在隔离环境中，先验证原版 Cap 0.5.9 可以构建，再只汉化设置页，验证源码构建后替换文件的方案是否成立。

## 顺序与验收

1. 环境准备：固定源码、JS 锁文件、Cargo 锁文件及工具链；安装依赖；记录首次构建日志。
2. 英文基线：构建未修改源码。确认启动、短录制、本地保存、再次打开和导出，保留测试产物的 SHA-256。
3. 小范围汉化：只改设置页用户可见文案，保持变量、快捷键、协议值和逻辑不变；检查 100%/125%/150% 缩放。
4. 部署研究：在独立测试安装中识别主程序、sidecar、FFmpeg/ONNX DLL 和资源之间的配套关系，不预设只替换一个 EXE。
5. 还原验证：对测试目录做备份/替换/还原，最终文件哈希与原始备份一致。P0 不覆盖日常安装。

## 不在本轮范围

完整翻译、补丁安装器、自动更新、发布签名、账号或会员逻辑、正式安装目录修改、录屏工程和个人设置迁移。

## 后续阶段

P0 通过后再决定 P1 完整汉化、P2 安装/备份/还原工具及 P3 发布。安装器必须版本/架构/哈希校验，拒绝跨版本覆盖，重复安装不覆盖最初备份，失败明确报告回滚结果。

## 本轮交接

已完成源码获取、依赖盘点、工具版本固定和辅助脚本。磁盘空间及 LLVM/Rust 固定版本未补齐，完整依赖安装、编译和功能验收均未完成。先让用户决定构建工作区放在哪个磁盘，不清理或迁移用户文件。
