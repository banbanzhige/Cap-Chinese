# 开源发布清单

推荐先公开源码/完整补丁仓库。自用定位不免除向他人分发时的许可义务，源码公开也不自动完成所有第三方二进制分发审查。本文件是操作清单，不是法律合规认证。

## 当前已准备

- 面向使用者的 README、非官方声明、验证边界和贡献说明。
- AGPL v3 许可证原文、NOTICE、上游/参考项目许可副本。
- 覆盖本次改动的完整前端补丁与原生补丁，固定上游提交及环境模板。
- Git 忽略运行包、编译缓存、测试截图/浏览器快照、机器结果与敏感密钥文件。

## 第一次推送之前

- [ ] 核对公开的仓库名、维护者身份与联系方式；不填写假地址或占位邮箱。当前用仓库 Issues 反馈一般问题。
- [ ] 查看 `git status --short`，只添加明确要公开的文件，再检查 `git diff --cached --stat` 与 `git diff --cached`。
- [ ] 检查全部 Git 历史是否存在凭据、真实姓名、内部任务链接、机器路径或私人信息。忽略规则只防止新的误加入，不会清理历史。不要直接用 `git add -f` 加入测试目录。
- [ ] 确认 `translations/desktop-0.5.9.patch` 和 `translations/native-0.5.9.patch` 已加入；它们分别包含完整前端和原生修改，不能只发第一批设置补丁。
- [ ] 明确发布的是补丁工作区还是完整上游派生源码；不要让 README 暗示缺失的上游 checkout 已被提交。
- [ ] 不上传 `.playwright-cli`、`output`、`artifacts`、本地账号 store、完整运行日志或未经脱敏的截图。测试记录可能含用户名、窗口标题、应用路径等。
- [ ] 如历史中发现密钥，先撤销/轮换，再讨论清理历史；不要仅删除工作区文件。

本次没有执行 git add、提交、推送、GitHub 建仓、发布 Release 或改写历史。维护者确认内容后再执行这些操作。

## 公开 EXE/ZIP 之前（尚未全部完成）

- [ ] 使用经过验收的 R2 或更新版本，不发布存在 `frontendDist` 路径缺陷的早期包。
- [ ] 提供与二进制版本一致的完整应用源码、全部补丁、配置、必要构建说明和可访问的源码下载入口；验证解压后可按说明重建。现有源码包可作为候选，仍需检查新环境构建说明和第三方源码范围。
- [ ] 为实际随包 FFmpeg 7.1 full shared build 核对精确源代码、全部启用的外部库、许可证及构建材料，并安排符合适用 GPL/LGPL 条款的源码交付。只有 README 里的上游网址或 DLL 未修改这一事实不够自动证明合规。
- [ ] 核对 Visual Studio/Build Tools 对当前微软运行库文件的再分发资格及条款。无法确认时，不随包提供这些 DLL，改为指向微软官方运行库下载，并重新测试依赖；不要复制系统目录 DLL 来代替。
- [ ] 保留 ONNX Runtime LICENSE/ThirdPartyNotices，并逐项核对其他依赖、字体、音乐、图片和模型的来源与分发条件；不要把上游根 LICENSE 当作所有资产已获许可的证明。
- [ ] 新包包含项目 LICENSE/NOTICE、上游许可和第三方说明；核对每个二进制、源码包与 SHA-256 清单。
- [ ] 发布说明清楚标注未签名、Debug 构建、平台要求、已测/未测范围及数据目录；不要声称官方认可或完全兼容。
- [ ] 不打包 WebView2 缓存、账户信息、下载令牌、本机环境文件、真实录屏或测试快照。

现有本地 R2 ZIP 是自用测试交付物，未因增加这些文档而被修改或重新打包。之后生成新包时需重新核验，不能复用旧包哈希当作新包哈希。
